# DB MCP Gateway — Codebase Guide

Self-hosted app that lets developers connect PostgreSQL/MySQL databases through a web UI and expose them to AI coding agents via MCP.

## Architecture

```
src/index.ts          ← Hono HTTP server (port 4080), runs migrations on startup
src/api/routes/       ← REST CRUD for database connections
src/api/middleware/   ← Bearer token auth for /mcp
src/mcp/server.ts     ← McpServer + WebStandardStreamableHTTPServerTransport
src/mcp/tools/        ← list_databases, get_database_schema, get_table_schema, execute_read_query
src/db/schema.ts      ← Drizzle schema: database_connections, query_logs
src/db/client.ts      ← Drizzle + SQLite (better-sqlite3) internal control-plane DB
src/db/migrations/    ← SQL migrations (generated by drizzle-kit)
src/services/
  credentials.ts      ← AES-256-GCM encrypt/decrypt (NEVER log or return)
  connPool.ts         ← Per-DB query executor cache for external databases
src/query/safety.ts   ← Read-only enforcement + LIMIT injection
client/               ← React + Vite + Tailwind (built to client/dist/)
```

## Key commands

```bash
# Development
node src/index.ts              # start server (auto-runs migrations)
cd client && bun run dev       # React dev server with API proxy

# Testing
node --test src/**/*.test.ts   # 33 unit tests (no DB required)

# Database
bun run db:generate            # regenerate migrations from schema changes
bun run db:migrate             # apply pending migrations

# Build
bun run build:client           # build React app → client/dist/

```

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `DATABASE_PATH` | Yes | SQLite file path (internal control plane) |
| `ENCRYPTION_KEY` | Yes | 64-char hex (32 bytes). Generate: `openssl rand -hex 32` |
| `MCP_TOKEN` | Yes | Bearer token for /mcp. Generate: `openssl rand -base64 32` |
| `PORT` | No | HTTP port (default: 4080) |

## Security rules

- `encryptedCredentials` must **never** appear in API responses, logs, or error messages
- All `/mcp` requests require `Authorization: Bearer <MCP_TOKEN>`
- All SQL through `execute_read_query` must pass `assertReadOnly()` **and** use a read-only DB user
- `ENCRYPTION_KEY` is never stored in the database — it lives only in the environment

## MCP Tool Design for Agents

All MCP tools are designed to be **agent-friendly**:

- **Hints in output**: Each tool includes a `hint` field guiding the next step (e.g. "call get_table_schema next")
- **Structured errors**: Errors are JSON objects with `error` and `hint` fields, not bare strings
- **Filtering & search**: `get_database_schema` accepts an optional `filter` parameter to avoid dumping huge schemas
- **Row count & truncation**: `execute_read_query` returns `{ row_count, truncated, hint, rows }` so agents know if results were capped
- **Consistent field names**: Output field names match tool parameter names (e.g. `database_id`) for reduced confusion

### Adding a new MCP tool

1. Create `src/mcp/tools/myTool.ts` — export an async function
2. Register it in `src/mcp/server.ts` with `mcpServer.registerTool(...)`
3. **Always** include a `hint` field in JSON output pointing to the next logical tool or explaining limitations
4. Return structured errors: `{ error: "message", hint: "try X" }` instead of bare strings

## Adding a new API route

1. Create or extend a file in `src/api/routes/`
2. Mount it in `src/index.ts` with `app.route('/api/...', myRoutes)`

## Drizzle schema changes

1. Edit `src/db/schema.ts`
2. Run `bun run db:generate` — creates a new SQL file in `src/db/migrations/`
3. Commit the migration file alongside the schema change
4. Migrations run automatically on next server start
