# DB MCP Gateway — Codebase Guide

Desktop app (Tauri 2; macOS, Windows, Linux) that lets developers connect their databases and expose them to AI coding agents on the same computer via MCP. Desktop-only: there is no web or hosted version and no Docker image. The backend in `src/` runs only as the app's Node sidecar and refuses to start without `APP_SESSION_TOKEN`. See docs/desktop-plan.md for the contracts (environment, IPC, paths).

## Architecture

```
desktop/src-tauri/          ← Tauri 2 shell (Rust): owns the sidecar, secrets, tray, IPC
  src/lib.rs                ← app setup, plugins, command registration
  src/main.rs               ← binary entry point
  src/supervisor.rs         ← spawns the Node sidecar, health checks, restart with backoff, stop
  src/secrets.rs            ← ENCRYPTION_KEY in OS keychain (keyring), 0600 file fallback
  src/settings.rs           ← settings.json (AppSettings)
  src/tray.rs               ← tray: status, Open, Restart server, Open logs, Quit
  src/commands.rs           ← IPC commands invoked by the UI (docs/desktop-plan.md Contract 2)
  src/ai_clients.rs         ← installs/removes the db-mcp entry in AI client configs
  resources/server/         ← sidecar bundle + migrations (generated, gitignored)
  binaries/                 ← bundled Node 26 binary (generated, gitignored)
scripts/build-sidecar.mjs   ← esbuild bundle of src/ → resources/server/, fetches Node 26
src/index.ts                ← Hono sidecar entry (port 4080); runs migrations on startup
src/api/routes/             ← REST CRUD for database connections
src/api/middleware/         ← localGuard.ts: Host allowlist, /mcp Origin rejection, /api Origin + X-App-Session
src/mcp/server.ts           ← McpServer + WebStandardStreamableHTTPServerTransport
src/mcp/tools/              ← list_databases, get_database_schema, get_table_schema, execute_read_query
src/db/schema.ts            ← Drizzle schema: database_connections, query_logs
src/db/client.ts            ← Drizzle + SQLite (better-sqlite3) internal control-plane DB
src/db/migrations/          ← SQL migrations (generated by drizzle-kit)
src/services/
  credentials.ts            ← AES-256-GCM encrypt/decrypt (NEVER log or return)
  connPool.ts               ← Per-DB query executor cache for external databases
src/query/safety.ts         ← Read-only enforcement + LIMIT injection
client/src/                 ← React + Vite + Tailwind UI, bundled into the Tauri app (built to client/dist/)
client/src/platform/        ← UI platform adapter: tauri.ts (IPC) is the only implementation
```

## Key commands

```bash
# Development (Vite dev server in the Tauri window; the shell starts the sidecar)
bun run dev                    # alias of desktop:dev
bun run desktop:dev            # rebuild sidecar, then `tauri dev`
bun run desktop:sidecar        # build only the Node sidecar bundle (optional: -- --target <triple>)
bun run desktop:build          # production bundle (tauri.conf.json runs the client and sidecar builds)
node scripts/ui-preview.mjs    # dev-only browser preview; starts the local backend and Vite

# Testing and checks
bun run test                   # node --test unit tests (no DB required)
bun run type-check             # tsc --noEmit
cd desktop/src-tauri && cargo test

# Database
bun run db:generate            # regenerate migrations from schema changes
bun run db:migrate             # apply pending migrations (DATABASE_PATH, default ./data/db-mcp.sqlite)

# Build
bun run build:client           # build React app → client/dist/

```

Do not start `src/index.ts` directly: it exits unless `APP_SESSION_TOKEN` is set, and the shell is the only supported launcher.

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `DATABASE_PATH` | Yes | SQLite file path (internal control plane) |
| `ENCRYPTION_KEY` | Yes | 64-char hex (32 bytes). Generate: `openssl rand -hex 32` |
| `HOST` | No | Bind address (default: `127.0.0.1`) |
| `PORT` | No | HTTP port (default: 4080) |
| `APP_SESSION_TOKEN` | Yes | Per-launch token generated by the desktop shell. `/api/*` (except `GET /api/health`) requires `X-App-Session: <token>`. The server exits at startup if it is missing |
| `ALLOWED_ORIGINS` | No | Extra origins allowed on `/api`. The shell sets `http://localhost:5173` in debug builds only (Vite dev server inside the Tauri webview) |

## Security rules

- `encryptedCredentials` must **never** appear in API responses, logs, or error messages
- Request guards run on every route (`src/api/middleware/localGuard.ts`):
  - **Host allowlist**: `Host` must be `127.0.0.1:<PORT>`, `localhost:<PORT>` or `[::1]:<PORT>`, else 403 (blocks DNS rebinding)
  - **`/mcp`**: no bearer token; any `Origin` header → 403 (MCP clients are not browsers)
  - **`/api`**: `Origin` must be allowlisted (`tauri://localhost`, `http://tauri.localhost`, `https://tauri.localhost`, plus `ALLOWED_ORIGINS`), else 403. Allowed origins get CORS headers; preflight returns 204. `X-App-Session` must match `APP_SESSION_TOKEN` (constant-time compare), else 401
- Guards are registered before the routes they protect. Hono only runs middleware added ahead of a matching route
- All SQL through `execute_read_query` must pass `assertReadOnly()` **and** use a read-only DB user
- `ENCRYPTION_KEY` is never stored in the database — it lives only in the environment

## MCP Tool Design for Agents

All MCP tools are designed to be **agent-friendly**:

- **Hints in output**: Each tool includes a `hint` field guiding the next step (e.g. "call get_table_schema next")
- **Structured errors**: Errors are JSON objects with `error` and `hint` fields, not bare strings
- **Filtering & search**: `get_database_schema` accepts an optional `filter` parameter to avoid dumping huge schemas
- **Row count & truncation**: `execute_read_query` returns `{ row_count, truncated, hint, rows }` so agents know if results were capped
- **Consistent field names**: Output field names match tool parameter names (e.g. `database_id`) for reduced confusion

### Adding a new MCP tool

1. Create `src/mcp/tools/myTool.ts` — export an async function
2. Register it in `src/mcp/server.ts` with `mcpServer.registerTool(...)`
3. **Always** include a `hint` field in JSON output pointing to the next logical tool or explaining limitations
4. Return structured errors: `{ error: "message", hint: "try X" }` instead of bare strings

## Adding a new API route

1. Create or extend a file in `src/api/routes/`
2. Mount it in `src/index.ts` with `app.route('/api/...', myRoutes)`

## Drizzle schema changes

1. Edit `src/db/schema.ts`
2. Run `bun run db:generate` — creates a new SQL file in `src/db/migrations/`
3. Commit the migration file alongside the schema change
4. Migrations run automatically on next server start
